# Порядок работы

## 1. Перед изменениями

```powershell
git status
```

В репозитории может параллельно работать другой агент или человек. Если в дереве есть
чужие незакоммиченные изменения — **не трогайте их**: не делайте `git checkout .`,
`git reset --hard`, `git stash` и не коммитьте чужие файлы под своим сообщением.

Отдельное предупреждение: GUI-клиенты вроде GitHub Desktop могут автоматически выполнить
stash и переключить ветку прямо во время работы агента, оставив конфликтные маркеры.
Если вы видите `<<<<<<<` в файлах, которых не касались, — остановитесь и сообщите
пользователю, а не «чините» чужую работу молча.

Затем прочитайте:

- [`conventions.md`](conventions.md) — обязательные границы;
- `docs/architecture/dependency-map.md` — направление зависимостей;
- актуальный план в `docs/plans/` — что уже закрыто, а что намеренно нет.

## 2. Реализация

Направление зависимостей:

```
presentation (Next routes, React, CSS)
        v
application (scene, explorer, snapshot, asset, screen use cases)
        v
domain (иммутабельные типы, машины состояний, инварианты, порты)

infrastructure (browser, bridge, Tauri адаптеры) реализует порты
```

При правке `.proto` сразу выполните генерацию и закоммитьте результат:

```powershell
pnpm --filter @gremuchaya/protocol generate
```

## 3. Проверка

Минимум для любой задачи:

```powershell
pnpm format:check
pnpm typecheck
pnpm lint
pnpm test
pnpm check:ui-boundary
pnpm check:protocol-generation
```

Полный локальный шлюз:

```powershell
pnpm check
```

Дополнительно по обстоятельствам:

| Когда менялось               | Что запустить                                                                       |
| ---------------------------- | ----------------------------------------------------------------------------------- |
| UI и пользовательские потоки | `pnpm test:ui`                                                                      |
| Rust / `src-tauri`           | `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `pnpm test:cargo` |
| Сборка и экспорт             | `pnpm build:web`, `pnpm build:desktop:web`                                          |
| Перед днём съёмки            | `pnpm check:release`                                                                |

На каждый pull request CI прогоняет `pnpm format:check`, обе сборки, `pnpm test:ui` и
полный набор Rust-проверок независимо от того, что менялось. Строки выше — о том, что
стоит прогнать локально, а не о том, что запустится.

Запуск одного файла тестов:

```powershell
pnpm --filter @gremuchaya/hq test -- src/state/operationsStore.test.ts
pnpm --filter @gremuchaya/control-plane test -- src/sync/runtime.test.ts
```

## 4. Отчёт

Приводите **реальный вывод** с числами, а не утверждение «всё проходит». Явно
перечисляйте, что осталось непокрытым.

Формулировки имеют значение: «слайс реализован и протестирован» — это не «фаза закрыта».
Не переводите фазу в закрытое состояние, пока не пройден весь её шлюз.

Если отрицательный тест должен доказывать защиту от регрессии — убедитесь, что он падает
при откате исправления, и укажите это в отчёте.

## 5. Коммит

Conventional Commits:

```
<тип>(<область>): <краткое описание в повелительном наклонении>
```

Типы: `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`,
`revert`. Проверяется хуком `commit-msg`: он же отклоняет заголовок длиннее 100 символов и
строки, начинающиеся с `Co-Authored-By`, `Generated with` или `Assisted-by`.

Правила:

- **никаких `Co-Authored-By` и упоминаний ИИ-ассистентов** в сообщении;
- не коммитьте в `master` напрямую — работайте в ветке;
- индексируйте только свои файлы, перечисляя пути явно; `git add -A` захватит чужую
  незакоммиченную работу;
- перед коммитом просмотрите `git diff --cached --stat` и убедитесь, что в индексе нет
  секретов, `.env`, реальных путей монтирования и `*.local.json`.

Хук `pre-commit` форматирует и линтует только проиндексированные файлы, поэтому чужие
изменения он не затронет.

## 6. Обновление документации

- `docs/plans/` — если изменение продвигает фазу; сохраняйте честный учёт незакрытого;
- `docs/adr/` — если менялось архитектурное решение;
- `CLAUDE.md` и `.agents/` — если менялись команды или границы.
