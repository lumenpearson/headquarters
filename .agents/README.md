# `.agents`

Инструкции для ИИ-ассистентов и автоматизированных агентов, работающих с этим
репозиторием. Файлы здесь — источник правды для агентов, не зависящий от конкретного
ассистента. Ассистент-специфичные точки входа в корне (`CLAUDE.md`) должны ссылаться на
них, а не пересказывать: сейчас `CLAUDE.md` держит собственную копию тех же границ, и
расхождение между двумя копиями — дефект, а не вариант нормы.

| Файл                               | Назначение                                                                                                          |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| [`conventions.md`](conventions.md) | Границы, которые нельзя нарушать, и как их проверить                                                                |
| [`workflows.md`](workflows.md)     | Порядок работы: от задачи до коммита, включая шлюзы проверок                                                        |
| [`skills/`](skills/)               | Зеркала вендоренных скиллов из `.claude/skills/`, уложенные установщиком; правки вносятся в обе копии одной партией |

Определения специализированных агентов с их границами и инструментами лежат отдельно, в
`.claude/agents/`; этот каталог описывает правила, а тот — исполнителей.

## Быстрый старт для агента

1. Прочитайте [`conventions.md`](conventions.md) — там перечислены границы, которые
   проверяются скриптами, а не соглашением.
2. Прочитайте `docs/architecture/dependency-map.md` перед любой сквозной задачей.
3. Прочитайте актуальный план в `docs/plans/` — проект ведёт линейный учёт фаз и
   намеренно фиксирует, что ещё **не** закрыто.
4. Следуйте [`workflows.md`](workflows.md) при внесении изменений.

## Главные правила

- **Не помечайте фазу закрытой, пока её шлюз не пройден целиком.** План намеренно
  различает «слайс реализован и протестирован» и «фаза закрыта». Зелёный прогон тестов
  доказывает покрытый срез, а не смежные требования.
- **Доказательства вместо утверждений.** В отчёте приводите реальный вывод команд с
  числами, а не фразу «всё проходит».
- **Отрицательный тест должен ловить регрессию.** Убедитесь, что он падает при откате
  исправления, иначе он ничего не доказывает.
- **Не коммитьте `Co-Authored-By` и любые упоминания ИИ-ассистентов** в сообщениях
  коммитов.
- **Не трогайте чужую незакоммиченную работу.** В репозитории может параллельно
  работать другой агент или человек; сначала проверьте `git status`.
- **Секреты и реальные пути не попадают в репозиторий, логи и отчёты.** Используйте
  `*.example.json` и переменные окружения.
