# Self-hosting the control plane

Как поднять контрольную плоскость проекта на своей машине — со своей базой, своими секретами и
без учётной записи где бы то ни было.

Этот документ — единственное место, где описано, что даёт каждый уровень развёртывания.
`docs/release/environment.md` описывает развёртывание **этого проекта** (Vercel и Neon) и сюда
ссылается; `docs/release/known-limitations.md` перечисляет ограничения сборки и тоже ссылается
сюда. Решение и его причины — в `docs/adr/0010-container-deployment.md`.

## Что нужно

- Docker с Compose v2 (`docker compose version`).
- Node 20 или новее — только для `scripts/generate-env.mjs`. Он использует лишь встроенные модули
  `node:`, поэтому `pnpm install` не требуется. Файл `.env` можно написать и руками, скопировав
  `.env.example`; тогда Node не нужен вовсе, но секреты придётся придумать самостоятельно, а
  придуманный секрет — это подобранный секрет.

Собирается только `apps/control-plane`. Ни веб-приложение, ни настольная оболочка, ни file bridge в
образ не входят — почему, сказано в ADR-0010.

## Четыре команды

```powershell
node scripts/generate-env.mjs
docker compose up -d --build --wait
docker compose ps
docker compose down
```

Первая команда пишет `.env` рядом с `compose.yaml` и печатает **имена** переменных и путь к файлу —
никогда значения. Три секрета она берёт не у человека: пароль PostgreSQL, `HQ_CONTROL_PLANE_AUTH_TOKEN_PEPPER`
и `HQ_CONTROL_PLANE_BOOTSTRAP_SECRET` — это три независимых значения по 64 символа из
`randomBytes(48)`. Повторный запуск существующий файл не перезаписывает и завершается с кодом 1;
`--force` перезаписывает и тем самым обесценивает каждый выданный access-token, refresh-token и
код сопряжения.

Вторая команда собирает образ и ждёт, пока обе службы не станут `healthy`. Ожидание — не
формальность: контрольная плоскость становится здоровой только после того, как PostgreSQL принял
соединение, миграции прошли одной транзакцией под `pg_advisory_xact_lock`, а её собственная проба
подтвердила, что `sync.device-lifecycle` и `sync.realtime-admission` включены. Плоскость,
поднявшаяся в health-only режиме — потому что секрет отвергнут или база недоступна, — отвечает
`Health` со статусом `SERVING` и здоровой так и не станет.

Плоскость слушает `http://127.0.0.1:4100`. Порт публикуется только на loopback: content security
policy упакованной оболочки допускает loopback и `*.vercel.app` и не может допустить адрес вида
`192.168.x.x` (`docs/release/known-limitations.md`).

`docker compose down` останавливает стек и сохраняет том с базой. `docker compose down -v` удаляет
и том — вместе с группой, устройствами и журналом событий.

## Что даёт каждый уровень

| Уровень                      | Чем задан                                                                                                 | Что добавляет                                                                                                                  |
| ---------------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| **T0** health-only           | ни базы, ни секретов                                                                                      | `control.health`, `transport.connect`, `transport.grpc-web`. Список зависимостей в `Health` пуст. Группу создать нельзя.       |
| **T1** умолчание `compose`   | PostgreSQL из `compose.yaml` + `HQ_CONTROL_PLANE_AUTH_TOKEN_PEPPER` + `HQ_CONTROL_PLANE_BOOTSTRAP_SECRET` | `sync`, `sync.device-lifecycle`, `sync.realtime-admission`, `settings`, `materials`, `telemetry`, `integration`.               |
| **T2** T1 + Upstash Redis    | пара `HQ_CONTROL_PLANE_REDIS_REST_*` по HTTPS                                                             | ни одной новой capability — меняется поведение: присутствие замечает ушедшее устройство, публикации ограничиваются по частоте. |
| **T3** T2 или T1 + хранилище | пять `HQ_CONTROL_PLANE_STORAGE_*` по HTTPS                                                                | `materials.storage-grants`.                                                                                                    |

Полный список переменных с границами — в `apps/control-plane/.env.example`.

### Чего у T1 нет

Два ограничения, и оба названы честно, потому что обнаружить их иначе можно только на съёмке.

- **`materials.storage-grants` выключена.** `BeginUpload`, `CreateMaterialVersion`,
  `GetDownloadGrant` и `GetPreviewGrant` отвечают `FAILED_PRECONDITION` с именем недостающей
  конфигурации. Метаданные материалов, версии и корзина работают; загрузить или скачать файл
  нельзя. Нужен S3-совместимый bucket — AWS S3, Cloudflare R2 или MinIO; подписывание сделано на
  `node:crypto` без SDK, поэтому подойдёт любой из них.
- **Redis не задан.** Присутствие отдаёт последнее записанное устройством состояние и не может
  сообщить, что устройство ушло: строка в `presence_snapshots` не истекает. Групповые публикации не
  ограничиваются по частоте. Служба при этом работает, и `Health` говорит, какой из двух режимов
  действует.

Redis-службы в `compose.yaml` намеренно нет. `parseRedis` в `apps/control-plane/src/config.ts`
требует HTTPS-эндпоинт, поэтому контейнер с Redis-over-REST на `http://` будет отвергнут при
старте. Проверку не расширяют ради удобства контейнера: REST-токен в открытом канале — это
предъявительский секрет, который перехвативший повторит.

### Что есть у контейнера и нет у облачного развёртывания

`sync.realtime-admission`. Образ — это Node-адаптер: он владеет HTTP-сервером, на который вешается
обработчик WebSocket-upgrade, поэтому клиент идёт на сокет, а не на опрос. Развёртывание на Vercel
сокет держать не может (ADR-0009), и группа, которую кормит опрос, платит шестисекундный пол
задержки воспроизведения. Здесь этого пола нет.

Реплика ровно одна, и это записано в `compose.yaml`, а не оставлено умолчанию. Рассылка событий
живёт в одном процессе: две реплики обе пишут в `sync_events`, но ни одна не отдаёт события другой
в её сокеты, и аудитория каждой публикации молча делится пополам.

## Подключение оболочки

Адрес плоскости клиент не угадывает: `controlPlaneUrl` по умолчанию пуст
(`packages/config/src/projectSchemas.ts`), и без него не строится ни одного клиента. Напишите
адрес в `apps/hq/public/runtime/project.override.json` — git его игнорирует, образец лежит рядом:

```json
{ "controlPlaneUrl": "http://127.0.0.1:4100" }
```

Файл читается на старте приложения, а не на сборке, поэтому адрес меняется без пересборки —
в отличие от `NEXT_PUBLIC_HQ_CONTROL_PLANE_URL`, которая попадает в бандл. Когда заданы обе,
побеждает override.

Настольная оболочка сопрягается по `http://127.0.0.1:4100`. Для создания группы нужен
`HQ_CONTROL_PLANE_BOOTSTRAP_SECRET` — тот самый, что сгенерирован в `.env`; он предъявляется
заголовком `x-hq-bootstrap-secret` и защищает эту плоскость от того, кто до порта дотянулся.

Если браузер обращается к плоскости не с одного из четырёх разрешённых по умолчанию адресов,
допишите свой в `HQ_CONTROL_PLANE_ALLOWED_ORIGINS` в `.env`. Значение **заменяет** весь список
целиком, поэтому два адреса `tauri.localhost` должны в нём остаться.

## Обслуживание

- **Логи:** `docker compose logs control-plane`. Ошибки старта называют переменную, а не её
  значение.
- **Миграции** выполняются самим процессом при старте, до регистрации первого RPC. Развёртывание,
  которое предпочитает отдельный шаг, задаёт `HQ_CONTROL_PLANE_RUN_MIGRATIONS_ON_START=false` и
  запускает `node dist/migrate.js` — образ несёт эту точку входа.
- **Проба вручную:** `docker compose exec control-plane node dist/healthcheck.js --require-capability sync`.
  Код возврата 0 или 1, вывод — одна строка.
- **Готовый образ вместо сборки:** задайте `HQ_CONTROL_PLANE_IMAGE=ghcr.io/<owner>/<repository>/control-plane`
  и `HQ_IMAGE_TAG` — тег релиза или `edge`, — затем `docker compose pull` перед `up`.
- **Резервная копия** — это том `gremuchaya-hq_postgres-data`; в нём вся группа целиком.

Никакая строка подключения, ключ и токен не принадлежат репозиторию. `.env` игнорируется git, и в
issue, pull request или логе на их месте должно стоять `<redacted>`.

## Что здесь не доказано

- Ни одно развёртывание третьей стороной не выполнялось. Образ впервые собирается workflow
  `.github/workflows/container.yml`; ни `docker build`, ни `docker compose up` не запускались на
  машине, где эти файлы написаны, — Docker на ней не установлен.
- Smoke-тест в CI доказывает старт, миграции, `Health` и набор capability — и ничего сверх этого.
  Десять опциональных наборов PostgreSQL по-прежнему пропускаются: направить их на базу из
  `compose.yaml` сознательно оставлено за рамками.
- Multi-arch, подпись образа и SBOM отсутствуют. Собирается только `linux/amd64`.
- Опубликованный пакет GHCR остаётся приватным, пока его видимость не переключат вручную на
  странице пакета. Ни одно право workflow этого не даёт.
